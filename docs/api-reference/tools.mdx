## Authentication

Pass an Outlit API key in the `Authorization` header as `Bearer ok_...`.

## Request body

```json
{
  "tool": "outlit_list_customers",
  "input": {
    "limit": 10,
    "billingStatus": "PAYING"
  }
}
```

`tool` is a public tool name. The table below lists the main tools; [Integration tools](/api-reference/integrations)
also documents two compatibility handoff tools. `input` is the tool-specific object, validated
against the shared `@outlit/tools` contract before the tool runs.

## Supported tools

### Customers and people

| Tool | Purpose |
|---|---|
| `outlit_list_customers` | Browse and filter customers by billing status, activity recency, revenue, traits, or name |
| `outlit_list_users` | Browse and filter users by journey stage, activity recency, customer, traits, email, or name |
| `outlit_get_customer` | Get full details for one customer, with optional related sections |
| `outlit_get_customer_relationship` | Bounded relationship read model: categorized statements with source labels (no raw fact IDs or quotes) |
| `outlit_get_customer_credits` | Read imported credit pools, remaining credits, burn rate, and runway for one customer |

### Identity

|---|---|

| `outlit_merge_customers` | Preview then execute a two-phase customer merge by exact UUIDs |
| `outlit_get_customer_merge_status` | Track a merge operation by its operation ID |

### Attention

### Feedback

| Tool | Purpose |
|---|---|
| `outlit_submit_feedback` | Submit product feedback — bugs, ideas, or agent friction — to the Outlit team |

`outlit_submit_feedback` accepts `body` (required, trimmed, non-empty, at most 20,000
characters), optional `area` (trimmed, non-empty, at most 100 characters), and optional
`context` (a JSON object of at most 16 KiB serialized, for diagnostics such as the surface
or client version — never secrets or unnecessary customer data). It returns the recorded
feedback `id` and `createdAt` timestamp.

Submissions require authentication and are rate limited under a dedicated quota; they do not
consume paid plan API-call quota. Feedback is product intake, not a support ticket, and does
not guarantee a reply.

For schema-driven clients, `@outlit/tools` publishes tool input schemas as `publicToolContracts`.

## TypeScript client

Use `@outlit/tools` when you want the same tool names and input contracts that power the CLI, Pi package, and public tool gateway:

```bash
npm install @outlit/tools
```

```typescript
import { createOutlitClient, publicToolContracts } from "@outlit/tools"

const outlit = createOutlitClient({
  apiKey: process.env.OUTLIT_API_KEY!,
})

const result = await outlit.callTool(
  publicToolContracts.outlit_search_customer_context.toolName,
  {
    query: "What pricing concerns came up recently?",
    customer: "acme.com",
    sourceTypes: ["CALL", "EMAIL", "SUPPORT_TICKET", "OPPORTUNITY"],
    topK: 5,
  },
)
```

The package also exports `publicToolContracts`, `publicToolNames`, server-defined `consumerToolPolicies`, `defaultToolNames`, `analyticalToolNames`, `piToolNames`, `cliToolNames`, `allPublicToolNames`, `publicOpenApiTransports`, `toolGatewayTransport`, `apiKeyValidationTransport`, `toolGatewayErrorCodes`, `toolGatewayErrorSchema`, `ingestTransport`, and enum lists such as `customerSourceTypes`. `OPPORTUNITY` is the canonical CRM opportunity source type; `CRM` and `CRM_OPPORTUNITY` are accepted input aliases.

## Examples

### List paying customers

```bash
curl -X POST https://app.outlit.ai/api/tools/call \
  -H "Authorization: Bearer ok_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "tool": "outlit_list_customers",
    "input": {
      "billingStatus": "PAYING",
      "limit": 10
    }
  }'
```

### Get customer details

```json
{
  "tool": "outlit_get_customer",
  "input": {
    "customer": "acme.com",
    "include": ["users", "revenue", "recentTimeline"],
    "timeframe": "30d"
  }
}
```

### Search customer context

```json
{
  "tool": "outlit_search_customer_context",
  "input": {
    "customer": "acme.com",
    "query": "What renewal concerns came up recently?",
    "sourceTypes": ["EMAIL", "CALL", "SUPPORT_TICKET", "OPPORTUNITY"],
    "after": "2026-01-01T00:00:00Z",
    "topK": 5
  }
}
```

### List active contact transition facts

```json
{
  "tool": "outlit_list_facts",
  "input": {
    "customer": "acme.com",
    "status": ["ACTIVE"],
    "sourceTypes": ["CALL", "OPPORTUNITY"],
    "factTypes": ["CONTACT_DEPARTURE", "CONTACT_POSITION_CHANGE", "CONTACT_DISENGAGEMENT"],
    "after": "2026-01-01T00:00:00Z",
    "limit": 20
  }
}
```

### Open one source record

```json
{
  "tool": "outlit_get_source",
  "input": {
    "sourceType": "OPPORTUNITY",
    "sourceId": "opp_123"
  }
}
```

### Read exact source content

Exact lookup can include a `contentPage` with bounded content segments. The default
page size is 10 segments, with a maximum of 100. Pass the returned
`contentPage.page.nextCursor` with the same source type and ID when
`contentPage.page.hasMore` is true. Check `contentPage.completeness` before treating
the content as complete.

```json
{
  "tool": "outlit_get_source",
  "input": {
    "sourceType": "CALL",
    "sourceId": "call_123",
    "limit": 10
  }
}
```

Example response with complete content:

```json
{
  "sourceType": "CALL",
  "sourceId": "call_123",
  "occurredAt": "2026-09-01T12:00:00Z",
  "title": "Renewal discussion",
  "summary": "The customer asked for a renewal proposal.",
  "permalink": null,
  "provider": "gong",
  "customer": { "id": "cust_123", "name": "Acme", "domain": "acme.com" },
  "participants": [],
  "record": {},
  "contentPage": {
    "sourceType": "CALL",
    "sourceId": "call_123",
    "contentKind": "call_transcript",
    "segments": [{ "id": "segment_1", "text": "Please send the renewal proposal." }],
    "page": { "returned": 1, "hasMore": false, "nextCursor": null },
    "completeness": { "status": "complete", "omittedFields": [] }
  }
}
```

### Follow person profile evidence

When a fact or search result references a `PERSON_PROFILE` source, use its source ID
for exact lookup. Replace the example ID with the ID from that reference.

```json
{
  "tool": "outlit_get_source",
  "input": {
    "sourceType": "PERSON_PROFILE",
    "sourceId": "snapshot_123"
  }
}
```

### Read customer features

```json
{
  "tool": "outlit_get_customer_features",
  "input": {
    "customer": "acme.com",
    "weeks": 12
  }
}
```

Feature usage is factual historical evidence. A feature can report complete or partial counts,
no matches in the requested window, or unavailable source evidence. Unavailable evidence is not
converted to zero. Archive is the available self-service lifecycle action.
Creating a Feature also creates the supporting weekly event-count and active-days metrics inside
Outlit; those metrics are not separate public resources.

### Submit product feedback

```json
{
  "tool": "outlit_submit_feedback",
  "input": {
    "body": "The merge preview did not list the losing record's traits.",
    "area": "customers",
    "context": { "surface": "cli", "command": "customers merge" }
  }
}
```

Returns `{ "id": "10000000-0000-4000-8000-000000000004", "createdAt": "2026-09-28T12:00:00.000Z" }`. See
[Feedback](#feedback) for input limits. Feedback is product intake, not a support ticket.

## Response

The response is the selected tool's JSON result. List tools return paginated collections; exact lookup tools return the matched record or an error when the record cannot be found. Search returns grouped artifact-level `source` and `fact` results, not raw vector chunks. Fact results include provenance fields such as `sourceType`, `sourceId`, `sourceOccurredAt`, `sourceQuote`, and `permalink` when available.

Money amounts such as `currentMrr`, `lifetimeRevenue`, and `accountImportance.arrCents` are in the billing provider's units for the currency they were billed in. For USD, EUR, GBP, and CAD these are cents: divide by 100 (for example, 1234500 is $12,345 in USD). Other currencies follow the provider's amount rules (see [Stripe's currency docs](https://docs.stripe.com/currencies)), so don't assume a divisor for them. Attention items return the currency alongside `arrCents`; customer results don't name it. ARR is 12 × `currentMrr` in the same units. The example below is for a customer billed in USD, so `"currentMrr": 25000` is $250 MRR.

Example list response:

```json
{
  "items": [
    {
      "id": "cus_123",
      "name": "Acme",
      "domain": "acme.com",
      "billingStatus": "PAYING",
      "activatedAt": "2026-01-15T09:30:00.000Z",
      "firstSeenAt": "2025-12-02T17:05:00.000Z",
      "lastActivityAt": "2026-04-10T18:22:11.000Z",
      "contactCount": 42,
      "currentMrr": 25000,
      "mrrCalculationStatus": "calculated",
      "owner": null,
      "daysSinceActivity": 3
    }
  ],
  "pagination": {
    "hasMore": true,
    "nextCursor": "cursor_abc",
    "total": 128
  }
}
```

## Error responses

Invalid JSON, unknown tool names, or invalid tool inputs return `400`:

```json
{
  "code": "INVALID_TOOL_INPUT",
  "message": "Invalid tool input",
  "retryable": false,
  "requestId": "req_123"
}
```

Invalid credentials return `401`. Plan API-call limits can return `402` or `429` with a stable billing `code`.
