## Authentication

Pass an Outlit API key in the `Authorization` header as `Bearer ok_...`.

## Request body

```json
{
  "tool": "outlit_list_customers",
  "input": {
    "limit": 10,
    "filters": { "billingStatus": ["paying"] }
  }
}
```

`tool` is a public tool name. The table below lists the main tools; [Integration tools](/api-reference/integrations)
also documents two compatibility handoff tools. `input` is the tool-specific object, validated
against the shared `@outlit/tools` contract before the tool runs.

## Supported tools

### Customers and people

| Tool | Purpose |
|---|---|
| `outlit_list_customers` | Browse and filter customers by billing status, activity recency, ARR, owner, customer fields (CRM, support tool or SDK traits), or name |
| `outlit_list_customer_fields` | List the fields Outlit holds about customers (CRM and support tool account fields, SDK traits), with their values, to filter customers on |
| `outlit_list_people` | Browse and filter the people at customers by journey stage, role, activity recency, customer, traits, email, or name, each with when they last took part in a conversation |
| `outlit_get_customer` | Get one customer, with optional sections: users, revenue, billing, relationship (a bounded summary with source labels), features, meters, credits and more |

### Identity

| Tool | Purpose |
|---|---|
| `outlit_get_identity` | Read a customer's bounded possible duplicate records and the evidence behind each; `include: ["links"]` adds its records in other systems |
| `outlit_list_merge_suggestions` | Browse saved merge suggestions and history; `include` adds impact, scope, Jev evidence and the cluster |
| `outlit_reject_merge_suggestion` | Reject one saved suggestion by `id`; needs a `requestId` |
| `outlit_merge_customers` | Two-phase customer merge by exact IDs: `mode: "preview"` (default, read-only) returns the impact, a linked-records diff and a `preview.token`; `mode: "execute"` needs that token and a `requestId` |
| `outlit_get_merge` | Track a merge by its `operation.id` |

### Attention

| Tool | Purpose |
|---|---|
| `outlit_list_cases` | List authorized open or resolved churn-risk cases (bounded fields, `preparedAction`, ARR at assessment as Money) |
| `outlit_get_case` | Retrieve one case by `id`, with evidence that names its `source` |

### Inbox

| Tool | Purpose |
|---|---|
| `outlit_list_tasks` | List one section of your Inbox (today, open, snoozed, done or pool), as tasks in the To do page's order, each with its task `id`, type, what it is part of and what it answers |
| `outlit_get_task` | Retrieve one Inbox task by `id`; `include` adds `source`, `draft` (opt-in) and `covered` |
| `outlit_act_on_task` | Act on your own Inbox task by `id` (done, won't do, wrong, reopen, snooze, unsnooze, take, put back, not covered, recover cover), as you would on the To do page; needs a `requestId`; returns an `undo` |
| `outlit_undo_task_action` | Undo an action with its `undo.token` (as `undoToken`); needs a `requestId` |

|---|---|
| `outlit_list_members` | Browse internal workspace members such as CSMs, managers, account owners, and admins |

| `outlit_set_customer_access` | Set a member's access to a customer to viewer, editor, or none; returns an undo token |

### Feedback

| Tool | Purpose |
|---|---|
| `outlit_submit_feedback` | Submit product feedback — bugs, ideas, or agent friction — to the Outlit team |

`outlit_submit_feedback` accepts `body` (required, trimmed, non-empty, at most 20,000
characters), optional `area` (trimmed, non-empty, at most 100 characters), and optional
`context` (a JSON object of at most 16 KiB serialized, for diagnostics such as the surface
or client version — never secrets or unnecessary customer data). It returns the recorded
feedback `id` and `createdAt` timestamp.

Submissions require authentication and are rate limited under a dedicated quota; they do not
consume paid plan API-call quota. Feedback is product intake, not a support ticket, and does
not guarantee a reply.

For schema-driven clients, `@outlit/tools` publishes tool input schemas as `publicToolContracts`.

## TypeScript client

Use `@outlit/tools` when you want the same tool names and input contracts that power the CLI, Pi package, and public tool gateway:

```bash
npm install @outlit/tools
```

```typescript
import { createOutlitClient, publicToolContracts } from "@outlit/tools"

const outlit = createOutlitClient({
  apiKey: process.env.OUTLIT_API_KEY!,
})

const result = await outlit.callTool(
  publicToolContracts.outlit_search_customer_context.toolName,
  {
    query: "What pricing concerns came up recently?",
    customer: "acme.com",
    limit: 5,
    filters: { sourceTypes: ["call", "email", "support_ticket", "opportunity"] },
  },
)
```

The package also exports `publicToolContracts`, `publicToolNames`, server-defined `consumerToolPolicies`, `defaultToolNames`, `analyticalToolNames`, `piToolNames`, `cliToolNames`, `allPublicToolNames`, `publicOpenApiTransports`, `toolGatewayTransport`, `apiKeyValidationTransport`, `toolGatewayErrorCodes`, `toolGatewayErrorSchema`, `ingestTransport`, and enum lists such as `sourceTypes`. The context tools take and return lowercase values (`email`, `calendar_event`, `churn_risk`). `opportunity` is the source type for CRM opportunities; `CRM` and `CRM_OPPORTUNITY` are older input spellings. `invoice` is the Stripe invoice source type; `outlit_get_source` and `outlit_list_sources` also accept `STRIPE_INVOICE` as an older spelling, but search and `outlit_list_facts` do not.

## Examples

### List paying customers

```bash
curl -X POST https://app.outlit.ai/api/tools/call \
  -H "Authorization: Bearer ok_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "tool": "outlit_list_customers",
    "input": {
      "filters": { "billingStatus": ["paying"] },
      "limit": 10
    }
  }'
```

### Get customer details

```json
{
  "tool": "outlit_get_customer",
  "input": {
    "customer": "acme.com",
    "include": ["users", "revenue", "recentTimeline"],
    "timeframe": "30d"
  }
}
```

### Read a Stripe invoice

Use `invoice` (`outlit_get_source` and `outlit_list_sources` also accept `STRIPE_INVOICE` as an older spelling) with the Stripe invoice ID. The record lists every stored line item: amounts, quantity, price, product, service period, whether it recurs or is one-off, and proration. Every amount is a Money value (`{ amount, currency, decimals, formatted }`).

```json
{
  "tool": "outlit_get_source",
  "input": {
    "source": { "type": "invoice", "id": "in_1PqExample" }
  }
}
```

### Read a customer's renewal date

```json
{
  "tool": "outlit_get_customer",
  "input": {
    "customer": "acme.com",
    "include": ["renewal"]
  }
}
```

Returns `"renewal": { "status": "available", "asOf": "...", "data": { "date": "2026-03-01", "source": "billing" } }`, the date the customer page shows. `source` is `outlit` (set in Outlit), `crm` (a CRM opportunity), or `billing` (the billing period of a yearly subscription). The section has status `empty` when the customer has none.

### Read a customer's CRM account fields

```json
{
  "tool": "outlit_get_customer",
  "input": {
    "customer": "acme.com",
    "include": ["crm"]
  }
}
```

Returns `crm.data`: one entry per CRM or support tool account linked to the customer, with `provider`, `connectionId`, `accountId`, `name`, the `owner` as that system records it, `recordUpdatedAt`, and `fields`: every non-empty field as stored, each with its `key`, `label`, `value` and whether it is `custom`. `contacts` lists the people that system associates with the account, whatever their email domain, most recently modified first: up to 25, each with `contactId`, `name`, `email`, `title` and `userId`, the customer's user with that contact or email (`null` when the person is not one of its users). More are counted in `omittedContactCount`. Fields past the response's size limit are counted in `omittedFieldCount` and named in `omittedFields` while they fit; ask for them with `crmFields`, by key or label. The section is enabled per workspace, and is absent until it is.

### Filter and list customers by customer fields

```json
{
  "tool": "outlit_list_customers",
  "input": {
    "filters": {
      "fields": [{ "field": { "source": "hubspot", "key": "lifecyclestage" }, "op": "eq", "value": "customer" }]
    },
    "fields": [{ "source": "hubspot", "key": "industry" }]
  }
}
```

`filters.fields` filters by customer fields: up to 10 filters, all of which must hold. A field's `source` is `hubspot`, `salesforce`, `attio`, `pylon` (the fields of the customers' CRM and support tool accounts, any linked account counting) or `traits` (traits sent with the Outlit SDK). `eq` and `in` compare text ignoring case; `gte` and `lte` compare numbers or ISO dates. `fields` (up to 5) adds `fields` to each customer: each field with its `label` and its `values`. Find a field's `source` and `key`, its picklist `options` and the values customers hold with `outlit_list_customer_fields`. Filters matching more than 5,000 customers are refused; add a narrower one.

`outlit_list_customers` filters are grouped under `filters`: `billingStatus` (an array of lowercase statuses), `arr` (`above`, `below`, `currency`; minor units), `fields`, `owner` (`id`, `email`, `has`), `activity` (`within`, `notWithin`, `activatedSince`), `renewal` (`within` one of `next_30d` to `next_365d`, or `after` and `before` as `YYYY-MM-DD` UTC dates; customers with no stored renewal date never match) and `search`. `orderBy` `renewal_date` sorts by the stored renewal date (ascending by default, customers with none last), and each customer carries `renewal: { date, source } | null`. The earlier top-level spellings (`billingStatus`, `arrAbove`, `arrBelow`, `arrCurrency`, `mrrAbove`, `mrrBelow`, `traitFilters`, `crm`, `crmFields`, `search`, `ownerId`, `ownerEmail`, `hasOwner`, `hasActivityInLast`, `noActivityInLast`, `activatedSince`), uppercase billing statuses and the `orderBy` values `arr_cents`, `mrr_cents` and `first_seen_at` are mapped to the new ones until 2026-12-11, and refused with the new name after that. `outlit_list_crm_fields` is now `outlit_list_customer_fields`, with `provider` renamed `source`.

### Read a contact's or deal's CRM fields

`outlit_list_people` with `"include": ["crm"]` (or `outlit_get_customer` with `"include": ["users", "crm"]`) adds `crm` to each user: the CRM contacts linked to them, with `fields` in the same shape as account fields. `outlit_get_source` on an `opportunity` adds the deal's `fields`. The same size limit applies: fields left out are counted in `omittedFieldCount`, and contacts left out are counted in `omittedCrmContacts`. A user has no `crm` when the section is not enabled for the workspace or when the size limit left no room for them; ask for fewer users or `crmFields` to get it.

### Search customer context

```json
{
  "tool": "outlit_search_customer_context",
  "input": {
    "customer": "acme.com",
    "query": "What renewal concerns came up recently?",
    "filters": {
      "sourceTypes": ["email", "call", "support_ticket", "opportunity"],
      "after": "2026-01-01T00:00:00Z"
    },
    "limit": 5
  }
}
```

Omit `customer` to search across all customers. The top-level `customer` is the
customer you scoped to, or `null` for a search across customers. Each `source` and
`fact` result also carries a `customer` (`id`, `name`, `domain`) naming the customer
it belongs to. A result's `customer` is `null` when it can't be attributed to exactly
one customer you can read. When nothing matches, `results` is empty and
`coverage.searched` says what was searched.

`customer` takes an ID, a domain or a name, the same on every context tool. The
earlier top-level `topK`, `sourceTypes`, `after` and `before` (and `sourceType` on
`outlit_list_sources`, `startDate`/`endDate`/`timeframe`/`channels`/`eventTypes` on
`outlit_get_timeline`, `status`/`factTypes`/`factCategories` on `outlit_list_facts`, and
`sourceType`/`sourceId` on `outlit_get_source`), uppercase values, and the source aliases
`CRM`, `CRM_OPPORTUNITY` and `STRIPE_INVOICE` are mapped to the new ones until 2026-12-11,
and refused with the new name after that.

```json
{
  "tool": "outlit_search_customer_context",
  "input": {
    "query": "Who raised security concerns?",
    "limit": 5
  }
}
```

### Read exact source content

Exact lookup can include `content`, a section with bounded content segments. Only
`content.status: "available"` has `data`. The default page size is 10 segments, with a
maximum of 100. Pass the returned `content.data.page.nextCursor` with the same source
when `content.data.page.hasMore` is true; until then the content is partial.
`content.data.omittedFields` names record fields left out.

```json
{
  "tool": "outlit_get_source",
  "input": {
    "source": { "type": "call", "id": "call_123" },
    "limit": 10
  }
}
```

### Read customer features

```json
{
  "tool": "outlit_get_customer",
  "input": {
    "customer": "acme.com",
    "include": ["features", "meters"],
    "features": { "weeks": 12 }
  }
}
```

`include` also takes `relationship` (a summary and at most eight current statements), `meters` (Autumn metered quantities that are not credits) and `credits` (Autumn credit pools). `features`, `meters` and `credits` come in pages of 25 by default, at most 100: pass `features`, `meters` or `credits` with `limit` and `cursor` to page one of them.

Feature usage is factual historical evidence. A feature can report complete or partial counts,
no matches in the requested window, or unavailable source evidence. Unavailable evidence is not
converted to zero. Archive is the available self-service lifecycle action.
Creating a Feature also creates the supporting weekly event-count and active-days metrics inside
Outlit; those metrics are not separate public resources.

### Admin tools

The admin tools change a workspace, so they share a few rules.

- **Retries.** Writes that can be sent twice take a `requestId`, any unique string (`outlit_create_destination`, `outlit_archive_destination`, `outlit_set_customer_owner`, `outlit_set_customer_access`, `outlit_setup_integration`, `outlit_create_feature`, `outlit_archive_feature`). A retry with the same `requestId` and input returns the first result; a changed input with the same id is refused.
- **Previews.** `outlit_archive_destination`, `outlit_archive_feature` and `outlit_set_customer_owner` change nothing on the first call. They return `preview.token`, what the change would affect, and `next`, the exact call to confirm. Confirm with the same target, `"mode": "execute"` and `"previewToken"`. A token lasts 15 minutes; a token that no longer matches the current state is refused with `preview_stale` and a fresh preview.
- **Undo.** `outlit_set_customer_owner` and `outlit_set_customer_access` return `undo: { token, until }` (24 hours), or `null` when the change cannot be undone. Call the same tool with `{ "undoToken", "requestId" }` to put the earlier state back. When the caller could not undo a change, such as removing their own access, the first call returns `outcome: "needs_confirmation"` with the reason, a preview and `next`.
- **Set state.** `outlit_update_destination` and `outlit_update_settings` take the end state; only the fields you send are written. `revision` is optional: when it is stale the call is refused with `stale_revision`, unless every field you asked for already holds its value.
- **Shapes.** Lists return `items` and `page { hasMore, nextCursor, total }` (25 per page by default, at most 100), and `coverage` when empty. People are `{ id, name, email }`; customers `{ id, name, domain }`. Enums are lowercase. A missing permission is `TOOL_CALL_FORBIDDEN` with `missingPermission`.

```json
{
  "tool": "outlit_set_customer_access",
  "input": {
    "customer": "acme.com",
    "member": "alex@example.com",
    "role": "viewer",
    "requestId": "6d1c8a6e-5c0b-4c0e-9d6a-2f5f6a2c9d11"
  }
}
```

| Earlier | Now |
|---|---|
| `outlit_get_destination {id}`, `outlit_list_destinations` → `{destinations}` | `outlit_list_destinations {ids: [id]}` → `{items, missing}`; `maskedConfig` is `config`, `syncStatus` and `lastSyncedAt` are `delivery`; each has a `revision` |
| `outlit_enable_destination`, `outlit_disable_destination` | `outlit_update_destination {id, enabled}` |
| `outlit_update_destination {id, type, label?, isDefault?}` | `{id, revision?, label?, isDefault?, enabled?}`; `type` is dropped |
| `outlit_create_destination {type: "SLACK_CHANNEL", ...}` → `{destination}` | `{type: "slack_channel", ..., requestId}` → `{created, destination}` |
| `outlit_archive_destination {id}` archives at once | `{id, requestId}` previews; `{..., mode: "execute", previewToken}` archives |
| `outlit_assign_customer_owner {customerId, targetUserId}` | `outlit_set_customer_owner {customer, member, requestId}` |
| `outlit_grant_customer_access`, `outlit_update_customer_access` `{customerId, targetUserId, role: "VIEWER" \| "EDITOR"}` | `outlit_set_customer_access {customer, member, role: "viewer" \| "editor", requestId}` |
| `outlit_revoke_customer_access` | `outlit_set_customer_access {..., role: "none"}` |
| `outlit_list_workspace_users {search, role, ..., orderBy: "owned_customer_count"}`, up to 1000 per page | `outlit_list_members {filters: {search, role, managerEmail, hasOwnedCustomers}, orderBy: "owned_customers" \| "name"}`, up to 100 per page; `ownedCustomerCount` is `ownedCustomers` |
| `outlit_get_integration_capabilities`, `outlit_get_integration_status`, the earlier `outlit_list_integrations {connectedOnly}` | `outlit_list_integrations {provider?, filters: {connected?}}` → `items[]` with `status`, `setup {auth, mode}`, `connection` |
| `outlit_begin_integration_setup {provider}` | `outlit_setup_integration {provider, handoff: true, requestId}` → `step: {kind: "browser_handoff", url, sessionId, expiresAt}` |
| `outlit_setup_integration` → `next`, `error {code: "OWNER_REQUIRED"}`; `outlitStage: "Won"` | `step`, `problem {code: "owner_required", ...}`; `next` is a next call; `outlitStage: "won"` |
| `outlit_get_integration_setup_status {sessionId}` | `outlit_get_setup_session {sessionId}` → `{sessionId, provider, status, pollAfterSeconds?, next?}` |
| `outlit_get_workspace_settings`, `outlit_get_customer_activation` | `outlit_get_settings` → `{settings: {general, activation}, revision}` |
| `outlit_update_workspace_settings {defaultTimezone, customerOwnership}`, `outlit_update_customer_activation {eventName}` | `outlit_update_settings {revision?, timezone?, defaultOwner?, activationEvent?}` → `{settings, revision, changed}` |
| `outlit_preview_customer_activation {eventName}` → `{preview: {...Count}}` | `outlit_preview_activation {event}` → `{customers, contacts, examples}` |
| `outlit_list_features {sourceKey, weeks, candidateLimit: 100}`, always with evidence and candidates | `{filters: {sourceKey, eventSearch}, include: ["usage", "candidates"], weeks, candidateLimit: 25, limit, cursor}`; `features` is `items`, `evidence` is `usage`, `selectedSourceKey` is `sources[].selected`, `workspaceActiveFeatureCount` is `workspaceActiveFeatures`, candidates are a section |
| `outlit_create_feature`, `outlit_archive_feature {id, revision}` | `requestId` added; archive previews first |

Each earlier name and input spelling keeps working until 2026-12-11.

## Response

The response is the selected tool's JSON result. List tools return paginated collections; exact lookup tools return the matched record or an error when the record cannot be found. Search returns grouped artifact-level `source` and `fact` results, not raw vector chunks. Every source is a `source` of `{ type, id }` that `outlit_get_source` opens as it is; a fact's `source` also carries `occurredAt`, `quote` and `permalink` when available.

Money is always `{ "amount", "currency", "decimals", "formatted" }`: `amount` is an integer in the billing provider's minor units for the currency, `decimals` is how many digits follow the decimal point (so `amount / 10^decimals` is the major-unit value), and `formatted` is ready to display (for example 1234500 is "$12,345.00" in USD). Other currencies follow the provider's amount rules (see [Stripe's currency docs](https://docs.stripe.com/currencies)). Customer `arr` is the annualized revenue run rate, the same figure the Outlit app shows: `arr.value` is the money, and `estimated` is `true` when the amount includes a usage or per-seat estimate. `arr.value.amount` is `0` for a churned, paused, or trialing customer, and `arr` is `null` when the app shows none. `outlit_get_customer` returns `revenue.data.arr` with the customer's `lifecycle` and the `parts` it is counted from. Cases return `importance.arrAtAssessment` as Money. The example below is for a customer billed in USD, so `"amount": 300000` is $3,000.00 ARR.

The legacy monthly `currentMrr` and `mrrCalculationStatus` fields are removed from customer results. Customer lists and reads use lowercase billing statuses (`none`, `trialing`, `paying`, `past_due`, `churned`), `page` for pagination, and `outlit.firstSyncedAt` for when Outlit first synced the customer (formerly `firstSeenAt`). Each section `outlit_get_customer` includes is `{ "status": "available", "asOf", "data" }`, or a `status` of `empty`, `not_connected`, `not_synced` or `unavailable` with a `reason`.

## Error responses

Invalid JSON, unknown tool names, or invalid tool inputs return `400`:

```json
{
  "code": "INVALID_TOOL_INPUT",
  "message": "Invalid tool input",
  "retryable": false,
  "requestId": "req_123"
}
```

Invalid credentials return `401`. Plan API-call limits can return `402` or `429` with a stable billing `code`.

A request id that was already used with different input returns `409` with the code `IDEMPOTENCY_CONFLICT`; send a new request id, or repeat the original input. A result larger than 64 KiB is never returned whole: a list returns the items that fit with a `truncation` field whose `next` names the call for the rest, and anything else returns `413` with the code `TOOL_RESULT_TOO_LARGE` and a `next` saying how to ask for less.

### Response headers

Beside the result, the gateway can send these headers. `@outlit/tools` reports them through the client's `onResponse` option, the CLI prints deprecations and notices to stderr, and Pi adds them as a second text block after the result.

| Header | Meaning |
|---|---|
| `outlit-deprecation` | The call used a retired tool name. JSON `{ "tool", "use", "until", "message" }`: the name you called, the tool to call instead, and the last day the old name works. `Deprecation` and `Sunset` carry the same information as standard headers |
| `outlit-notice` | A JSON array of sentences about an old input spelling the gateway changed, such as a limit lowered to the maximum or a 12-hour window rounded up to one day |
| `idempotent-replayed` | `true` when the result was stored from an earlier call with the same request id |

Retired tool names answer until the date in their `outlit-deprecation` header, then return `INVALID_TOOL_INPUT` with the issue code `renamed_tool` and the new name in `next.tool`.
