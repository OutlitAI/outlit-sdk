---
title: "Integration Capabilities"
description: "Call safe integration capabilities through the public tool gateway"
---

Integration automation uses `POST /api/tools/call`; there are no public integration credential, setup-step, or disconnect REST routes. Complete secret-bearing and provider-specific setup in the Outlit web app.

All gateway requests use an Outlit bearer:

```http
Authorization: Bearer ok_...
```

## Available tools

| Tool | Purpose |
|------|---------|
| `outlit_list_integrations` | List integrations and safe connection health |
| `outlit_get_integration_capabilities` | Describe browser-handoff or human-controlled setup modes |
| `outlit_begin_integration_setup` | Start a short-lived browser handoff |
| `outlit_get_integration_status` | **Preferred:** return one concise canonical agent-oriented readiness status |
| `outlit_get_integration_setup_status` | Legacy compatibility: poll a handoff owned by the current actor |

## Example

```bash
curl -X POST https://app.outlit.ai/api/tools/call \
  -H "Authorization: Bearer ok_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "tool": "outlit_begin_integration_setup",
    "input": { "provider": "hubspot" }
  }'
```

A successful handoff returns `provider`, `state`, `sessionId`, `connectUrl`, and `expiresAt`. Providers whose credentials or configuration cannot safely cross a model boundary report `setupMode: "human_controlled"` from the capabilities tool.

The generated [OpenAPI specification](/openapi.json) contains the exact input and output schema for every public capability.

New agent integrations should call `outlit_get_integration_status`; they must not compose the legacy browser-session and sync responses. Its canonical states are `not_connected`, `awaiting_auth`, `setup_incomplete`, `synchronizing`, `ready`, and `needs_attention`.
