---
title: "Ingest events"
description: "Send tracking events to Outlit."
openapi: "openapi.json POST /api/i/v1/{publicKey}/events"
---

Use your organization's `pk_` public key in the URL path. Ingest requests do not use a bearer API key.

## Request body

```json
{
  "visitorId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "source": "client",
  "events": [
    {
      "type": "pageview",
      "url": "https://example.com/pricing",
      "path": "/pricing",
      "title": "Pricing - Example",
      "referrer": "https://google.com",
      "timestamp": 1699999999999
    }
  ]
}
```

For browser (`client`) tracking, send a UUID `visitorId`; server events can omit it when an event
provides `email`, `userId`, `fingerprint`, or `customerId` for identity or account attribution.
`source` defaults to `client` and also accepts `server` or `integration`. Send 1–100 events per request.

When a browser user is logged in, `userIdentity` can provide `email`, a system-owned `userId`, and
user `traits` for immediate resolution. `customerIdentity` can provide a system-owned `customerId`
and `customerTraits` for account attribution across the whole batch.

## Event types

All events share these common fields:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | string | Yes | Event type (see below) |
| `timestamp` | number | No | Unix timestamp in milliseconds. Defaults to server time. |
| `url` | string | Yes | Full page URL |
| `path` | string | Yes | URL path (e.g., `/pricing`) |
| `referrer` | string | No | Referrer URL |
| `utm` | object | No | UTM parameters (see below) |

### UTM parameters

```json
{
  "utm": {
    "source": "google",
    "medium": "cpc",
    "campaign": "spring_2024",
    "term": "pricing software",
    "content": "header_cta"
  }
}
```

### Pageview event

Track a page view.

```json
{
  "type": "pageview",
  "url": "https://example.com/pricing?plan=pro",
  "path": "/pricing",
  "title": "Pricing - Example",
  "referrer": "https://google.com/search?q=example",
  "utm": {
    "source": "google",
    "medium": "cpc",
    "campaign": "spring_2024"
  },
  "timestamp": 1699999999999
}
```

Set `type` to `pageview`. `title` is the page title when available.

### Custom event

Track any custom event.

```json
{
  "type": "custom",
  "url": "https://example.com/pricing",
  "path": "/pricing",
  "eventName": "button_clicked",
  "properties": {
    "buttonId": "cta-hero",
    "page": "/pricing",
    "variant": "A"
  },
  "timestamp": 1699999999999
}
```

Set `type` to `custom` and provide an `eventName`. The optional `properties` map accepts string,
number, boolean, and null values.

### Form event

Track a form submission.

```json
{
  "type": "form",
  "url": "https://example.com/contact",
  "path": "/contact",
  "formId": "contact-form",
  "formFields": {
    "email": "jane@example.com",
    "name": "Jane Doe",
    "company": "Acme Inc",
    "message": "I'd like to learn more..."
  },
  "timestamp": 1699999999999
}
```

Set `type` to `form`. `formId` is the form's ID or name; `formFields` holds field names and values.

<Warning>
  Do not send passwords, payment details, or national identifiers. Outlit filters `formFields` using a field denylist and sensitive-value checks; these safeguards do not replace filtering at the source.
</Warning>

### Identify event

Identify the visitor with their email/userId.

```json
{
  "type": "identify",
  "url": "https://example.com/signup",
  "path": "/signup",
  "email": "jane@example.com",
  "userId": "usr_12345",
  "customerId": "cust_123",
  "traits": {
    "name": "Jane Doe",
    "company": "Acme Inc",
    "plan": "enterprise",
    "role": "admin"
  },
  "customerTraits": {
    "plan": "enterprise",
    "seats": 50
  },
  "timestamp": 1699999999999
}
```

Set `type` to `identify` and provide at least one of `email` or your system-owned `userId`.
`traits` updates the user profile. Send your system-owned `customerId` to link that external
account or workspace to the resolved contact; `customerTraits` updates its profile.

### Engagement event

Track active time on a page. Automatically sent by the Outlit Browser SDK.

```json
{
  "type": "engagement",
  "url": "https://example.com/features",
  "path": "/features",
  "activeTimeMs": 45000,
  "totalTimeMs": 60000,
  "sessionId": "b2c3d4e5-f6a7-8901-bcde-f12345678901",
  "timestamp": 1699999999999
}
```

Set `type` to `engagement`. Send `activeTimeMs` for visible-tab interaction time and `totalTimeMs`
for total wall-clock time on the page. `sessionId` is a UUID that groups engagement events and
resets after 30 minutes of inactivity or when the tab closes.

### Calendar event

Track calendar booking from embedded widgets (Cal.com, Calendly).

```json
{
  "type": "calendar",
  "url": "https://example.com/demo",
  "path": "/demo",
  "provider": "cal.com",
  "eventType": "30 Minute Demo",
  "startTime": "2024-03-15T10:00:00Z",
  "endTime": "2024-03-15T10:30:00Z",
  "duration": 30,
  "isRecurring": false,
  "timestamp": 1699999999999
}
```

Set `type` to `calendar` and `provider` to `cal.com`, `calendly`, or `unknown`.
`eventType` names the meeting; `startTime` and `endTime` use ISO 8601, `duration` is in minutes,
and `isRecurring` indicates a recurring meeting. `inviteeEmail` and `inviteeName` are available
only through server-side webhooks.

## Response

### Success response

```json
{
  "success": true,
  "processed": 3
}
```

`processed` counts the successfully processed events. Inspect `errors` when `success` is false.

### Partial success response (HTTP 207)

When some events succeed and others fail:

```json
{
  "success": false,
  "processed": 2,
  "errors": [
    {
      "index": 2,
      "message": "Invalid event type"
    }
  ]
}
```

### Error response

```json
{
  "success": false,
  "processed": 0,
  "errors": [
    {
      "index": -1,
      "message": "Invalid or inactive tracking configuration"
    }
  ]
}
```

## Server-side events

For server-side tracking, the `visitorId` field can be omitted. Identity is resolved from the event data, including customer-only attribution when `customerId` is provided:

- **Identify events**: Use `email` and/or `userId` fields, plus optional customer context
- **Custom events**: Include top-level `email`, `userId`, `fingerprint`, and/or `customerId` fields

```json
{
  "source": "server",
  "events": [
    {
      "type": "custom",
      "url": "server://user@example.com",
      "path": "/",
      "eventName": "payment_received",
      "email": "user@example.com",
      "userId": "usr_123",
      "customerId": "cust_123",
      "properties": {
        "amount": 99,
        "currency": "USD"
      }
    }
  ]
}
```

<Warning>
  Server events require identity or account attribution. Custom events need at least one of `email`, `userId`, `fingerprint`, or `customerId`; identify events need `email` or `userId`.
</Warning>

## Batching best practices

For high-volume tracking:

1. **Batch events** - Send multiple events per request (up to 100)
2. **Use background queue** - Don't block user actions
3. **Retry with backoff** - Handle temporary failures
4. **Flush on shutdown** - Send remaining events before exit

```javascript
// Example batching implementation
const eventQueue = []
const FLUSH_INTERVAL = 5000
const MAX_BATCH_SIZE = 100

function track(event) {
  eventQueue.push({ ...event, timestamp: Date.now() })
  
  if (eventQueue.length >= MAX_BATCH_SIZE) {
    flush()
  }
}

async function flush() {
  if (eventQueue.length === 0) return
  
  const events = eventQueue.splice(0, MAX_BATCH_SIZE)
  
  try {
    await fetch('/api/i/v1/pk_xxx/events', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        visitorId: getVisitorId(),
        source: 'client',
        events
      })
    })
  } catch (error) {
    // Re-queue failed events
    eventQueue.unshift(...events)
  }
}

setInterval(flush, FLUSH_INTERVAL)
window.addEventListener('beforeunload', flush)
```
