---
title: "Integrations"
description: "Inspect integrations and start safe browser setup handoffs from the CLI"
---

Integration commands use the public tool gateway. For readiness, agents and scripts should use the single preferred `outlit integrations status` command. It returns one canonical status projection instead of composing browser setup and provider sync reads.

<Info>
  Provider credentials, provider-specific configuration, and disconnect remain in the Outlit web app. The CLI does not accept secret-bearing `--config`, provider setup steps, or destructive disconnect commands.
</Info>

## Start setup

```bash
outlit integrations setup hubspot
outlit integrations setup hubspot --json
```

Interactive terminals open the returned `connectUrl` and use the canonical status projection during the bounded handoff wait. JSON mode returns the handoff data for an agent or script:

```json
{
  "status": "awaiting_auth",
  "provider": "hubspot",
  "state": "handoff_ready",
  "sessionId": "00000000-0000-4000-8000-000000000001",
  "connectUrl": "https://app.outlit.ai/integrations/connect",
  "expiresAt": "2026-08-04T22:00:00.000Z"
}
```

For a human-controlled provider, the command returns `status: "human_controlled"` and `controlPlaneUrl` without accepting or returning credentials.

### Stripe

Stripe uses the same OAuth browser handoff when the selected environment reports
`setupMode: "browser_handoff"`:

```bash
outlit integrations setup stripe
```

Do not pass Stripe credentials, webhook signing secrets, or other provider-specific arguments to
the CLI. Complete provider-specific configuration in the Outlit web app.
After authorization, Stripe sends app events to Outlit's preconfigured event destination. No
per-account webhook setup is required.
If setup reports `status: "human_controlled"`, complete setup in the Outlit web app instead.

## Check status

```bash
outlit integrations status hubspot --json
outlit integrations status
```

`status` returns `integrations`, each with one canonical state and the time Core last observed data.

| State | Meaning |
| --- | --- |
| `not_connected` | Setup has not started. |
| `awaiting_auth` | The current actor must complete the browser handoff. |
| `setup_incomplete` | A required Outlit setup step remains. |
| `synchronizing` | Outlit is waiting for first usable sync data. |
| `ready` | Core has observed its established usable-data evidence. |
| `needs_attention` | Setup or sync requires review in Outlit. |

`ready` does not mean that OAuth completed or that a connection row exists. Browser-session IDs and raw provider state remain internal. New agent workflows use `setup` to begin the safe handoff and `status` to observe readiness.

## Release dependency

The CLI change depends on the matching Core public tool. Deploy Core before publishing an SDK release that uses this command.
