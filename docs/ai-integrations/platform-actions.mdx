---
title: "Platform Configuration"
description: "Configure Outlit destinations and report settings through REST and CLI"
---

Outlit's public platform-configuration surface is intentionally narrow. Use it to manage masked Slack destinations and selected workspace/report settings. Hosted agents, automations, generic signals, identity merge suggestions, and notification actions are not public configuration APIs.

Use [Integration Routes](/api-reference/integrations) to connect external data sources such as Slack, Stripe, HubSpot, PostHog, or support tools.

## How the Surfaces Fit Together

| Surface | Use it when | Entry point |
|---------|-------------|-------------|
| REST API | You are building a schema-driven integration | [OpenAPI spec](/openapi.json) |
| CLI | You want a human or coding agent to configure Outlit from a terminal | [CLI commands](/cli/commands#destinations) |

The CLI preserves a resource-first interface over the public REST routes:

```bash
outlit destinations options --search ops --json
outlit destinations create --type slack --channel-id C0123456789 --label "#customer-ops" --default --json
outlit settings update --default-timezone America/Los_Angeles --json
outlit settings report options --search sales --limit 20 --json
outlit settings report update --slack-channel-id C0123456789 --slack-channel-name sales-alerts --json
```

## Current Scope

| Area | Read actions | Write actions |
|------|--------------|---------------|
| Destinations | List destinations, get one destination with masked configuration, show Slack channel options | Create, update, enable, disable, archive, set default destination |
| Settings | Get workspace and report settings; search Slack-backed report setting options | Update default timezone and report Slack channel |

Destination updates patch only the fields provided. Destination responses expose masked configuration and never return raw secrets or unmasked provider settings.

## Safety Model

- Read actions require an API key with the `agents:read` scope.
- Write actions require an API key with the `agents:write` scope.
- `destinations options` is non-mutating, but requires `agents:write` because it lists Slack channel choices used to create destinations.
- Responses are projected public DTOs rather than raw database rows.
- The OpenAPI specification is the canonical source for request and response schemas.

## Available REST Routes

| Route | Purpose |
|-------|---------|
| `GET /api/destinations/options` | Show destination schemas and Slack channel options |
| `GET /api/destinations` | List destinations with masked configuration |
| `GET /api/destinations/{id}` | Get one destination with masked configuration |
| `POST /api/destinations` | Create a Slack channel destination |
| `PATCH /api/destinations/{id}` | Update a Slack channel destination |
| `POST /api/destinations/{id}/enable` | Enable a destination |
| `POST /api/destinations/{id}/disable` | Disable a destination |
| `POST /api/destinations/{id}/archive` | Archive a destination |
| `GET /api/settings` | Get workspace settings |
| `PATCH /api/settings` | Update workspace settings such as default timezone |
| `GET /api/settings/report` | Get report settings |
| `PATCH /api/settings/report` | Update report Slack channel settings |
| `GET /api/settings/report/options` | Search Slack channel options for report settings |

The [OpenAPI spec](/openapi.json) is the canonical reference for the complete public contract.
