`@outlit/pi` registers Outlit customer intelligence tools inside [Pi](https://github.com/mariozechner/pi-coding-agent). Use it when you want a Pi agent to query complete customer profiles, timelines, facts, sources, and customer-context search results through Outlit's public tool gateway.

## Install

```bash
pi install npm:@outlit/pi
```

Set an Outlit API key before starting Pi:

```bash
export OUTLIT_API_KEY=ok_your_api_key
pi
```

## Default tools

The default Pi extension exposes the customer intelligence tools that are read-only, plus the two toolset tools:

| Tool | What it does |
|------|--------------|
| `outlit_list_customers` | Browse customers by billing status, activity, revenue, owner, customer fields, or name |
| `outlit_list_customer_fields` | List the fields Outlit holds about customers (CRM and support tool account fields, SDK traits), with the values customers hold, for filtering customers |
| `outlit_list_people` | Browse the people at customers by journey stage, role, activity, customer, traits, email, or name |
| `outlit_get_customer` | Retrieve one complete customer profile |
| `outlit_get_timeline` | Retrieve customer activity across product, billing, support, and conversation channels |
| `outlit_list_facts` | List structured facts with status, source type, date, and provenance filters |
| `outlit_get_fact` | Retrieve one exact fact |
| `outlit_get_source` | Retrieve one exact source record behind a fact or search result |
| `outlit_list_sources` | List concrete source records for a customer |
| `outlit_search_customer_context` | Search grouped source and fact results with natural language |
| `outlit_list_toolsets` | List Core's toolsets and the tools each holds, so the agent can tell you which one to enable |
| `outlit_load_toolset` | Summarize one toolset's tools, or return full definitions for up to 10 of them |

Pi registers tools when a session starts, so loading a toolset does not make its tools callable in that session; enable one with the `toolsets` option below.

A call that fails comes back to the agent as the tool result `{ "error": { code, message, retryable, requestId, ... } }` with the gateway's `next`, `missingPermission`, `validationIssues` and `retryAfterSeconds` when it sent them, not as a crash.

SQL tools are available through `@outlit/tools`, but they are not enabled by default in `@outlit/pi`. Use them only for agents that should run read-only SQL.

## Minimal extension

If you only need the Outlit tools and the bundled `outlit` Pi skill, the package default is enough:

```ts
import { createOutlitPiExtension } from "@outlit/pi"

export default createOutlitPiExtension()
```

The extension reads `OUTLIT_API_KEY` from the environment and uses `https://app.outlit.ai` by default.

## Custom toolsets

Pass `toolNames` when you want a narrower or broader toolset, or `toolsets` to register every tool in Core's toolsets (`core`, `work`, `identity`, `admin`, `meta`); both apply when you pass both:

```ts
import { createOutlitPiExtension, piToolNames } from "@outlit/pi"

export default createOutlitPiExtension({
  toolNames: piToolNames,
})
```

```ts
export default createOutlitPiExtension({
  toolsets: ["core", "work"],
})
```

Use the default policy for ten read-only customer tools and the two toolset tools. Use `analyticalToolNames` when the agent also needs `outlit_get_schema` and read-only `outlit_query` (12 tools total, without the toolset tools). `piToolNames` is broader: it includes SQL, the toolset tools, customer ownership and access actions, Feature tools, workspace configuration, and `outlit_submit_feedback` for product feedback intake. Choose the smallest set your Pi agent needs.

## Growth agent examples

The [`examples/pi-agents`](https://github.com/OutlitAI/outlit-sdk/tree/main/examples/pi-agents) package shows four Pi agents built on `@outlit/pi` for revenue and retention work. It includes:

- Outlit customer intelligence, SQL, and schema tools registered in Pi
- the generic `outlit` skill from `@outlit/pi`
- a shared growth-agent skill with evidence-gathering playbooks
- a local usage-decay churn pretriage helper with a `churn.json` config
- slash commands and editable prompt templates for usage decay, friction-to-churn, activation failure, and expansion readiness

Try it locally from the SDK repo:

```bash
cd examples/pi-agents
npm install
export OUTLIT_API_KEY=ok_your_api_key
pi install -l .
pi
```

Then ask:

```text
/outlit-usage-decay-watchtower paying customers over $6,000 ARR
```

or:

```text
Which paying customers are active enough to be expansion candidates but blocked by plan limits?
```
