Outlit's MCP server lets MCP-compatible clients query customer data, manage customer ownership and access, and retrieve revenue metrics, timelines, facts, search results, and SQL analytics over a remote MCP connection.

The Outlit CLI is not required for MCP setup. Use the workspace MCP URL directly in your MCP client.

## Authentication model

Outlit's remote MCP endpoint supports both OAuth and scoped Outlit API keys. Both authentication methods expose the same public tool catalog; Outlit applies the permissions of the caller:

- OAuth calls use the signed-in member's current workspace permissions and customer access.
- API-key calls use the key's current workspace and explicit grants.

For most interactive MCP clients, OAuth is the simplest setup. In practice that means:
- you add the workspace MCP URL to your client
- you do not paste API keys or bearer headers into config files
- the client opens an OAuth sign-in flow and stores the resulting session

Headless clients that cannot complete OAuth may send an Outlit API key as their bearer credential. A tool remains unavailable unless the member permissions or API-key grants authorize its underlying command.

## Connect your MCP client

<Steps>
  <Step title="Copy your workspace MCP URL">
    Open [**Settings → CLI & MCP**](https://app.outlit.ai/settings/workspace/mcp) and copy the workspace-specific MCP URL for the workspace you want to connect.

    It looks like:

    ```text
    https://mcp.outlit.ai/w/<workspace-slug>/mcp?toolsets=core,work,meta
    ```

    Loads core, work and meta. Add admin or identity, or use `?toolsets=all` for every tool. The bare URL without `?toolsets` loads every tool, which is a long list for a client to carry; the slim URL keeps it short, and `outlit_list_toolsets` tells an agent how to add the rest.
  </Step>
  <Step title="Add the URL to your MCP client">
    Use your client's remote MCP / connector / server settings and add the Outlit URL directly.

    For clients that accept raw JSON config, the shape is typically:

    ```json
    {
      "mcpServers": {
        "outlit": {
          "url": "https://mcp.outlit.ai/w/<workspace-slug>/mcp?toolsets=core,work,meta"
        }
      }
    }
    ```

    No `Authorization` header is needed for OAuth-based customer-intelligence tools.
  </Step>
  <Step title="Complete OAuth in the client">
    After you add the server, your client should prompt you to sign in to Outlit and authorize access for that workspace.
  </Step>
  <Step title="Verify the connection">
    Ask your client:

    ```text
    Show me the available Outlit analytics views.
    ```
  </Step>
</Steps>

Before multi-step work, have your agent call `outlit_get_skill`. It returns the Outlit skill: when to use each tool, the order to call them in, and worked examples. For coding agents that run local commands, see [Agent skills](/ai-integrations/skills).

## Available tools

### Toolsets and the guide

| Tool | What it does |
|---|---|
| `outlit_get_skill` | Return the Outlit skill, the full guide to these tools. Read it once per session |
| `outlit_list_toolsets` | List the toolsets, their tools, and the MCP URL that adds one |
| `outlit_load_toolset` | Summarize a toolset's tools, or return the full descriptions and input schemas of up to 10 named tools |

### Customers and people

| Tool | What it does |
|---|---|
| `outlit_list_customers` | Filter customers by billing status, activity recency, revenue, owner, and customer fields such as CRM fields or exact trait values |
| `outlit_list_people` | Filter the people at customers by journey stage, role, activity, customer, and exact trait values; each carries when they last took part in a conversation |
| `outlit_list_members` | Browse internal workspace members such as CSMs, managers, account owners, and admins |
| `outlit_get_customer` | Get a customer profile and, with `include`, its users, revenue, billing, timeline, metrics, relationship summary, product-event features, Autumn meters and credit pools, each as a section with a status |

### Identity

| Tool | What it does |
|---|---|
| `outlit_get_identity` | Read a customer's possible duplicate records and the evidence behind each; `include: ["links"]` adds its records in other systems |
| `outlit_list_merge_suggestions` | Browse saved merge suggestions and history; `include` adds impact, scope, Jev evidence and the cluster |
| `outlit_reject_merge_suggestion` | Reject one saved suggestion by `id`, with an `idempotencyKey` so a retry never rejects twice |
| `outlit_merge_customers` | Two-phase customer merge by exact IDs: `mode: "preview"` (default, read-only, with a linked-records diff and a `preview.token`), then `mode: "execute"` with that token and an `idempotencyKey` |
| `outlit_get_merge` | Track a merge by its `operation.id`: status, phase and, after a failure, whether anything moved |

### Tasks and access

| Tool | What it does |
|---|---|
| `outlit_list_tasks` | List one section of your Inbox (today, open, snoozed, done or pool) as tasks, each with its task `id` |
| `outlit_get_task` | Retrieve one Inbox task by `id`; `include` adds its source, the prepared reply (`draft`, opt-in) and covered tasks |
| `outlit_act_on_task` | Act on your own Inbox task (done, won't do, snooze, take and more), returning an `undo` to pass to `outlit_undo_task_action`; needs an `idempotencyKey` |
| `outlit_undo_task_action` | Undo an action with the `undo.token` it returned (as `undoToken`), within `undo.until`; needs an `idempotencyKey` |
| `outlit_set_customer_owner` | Assign a customer's primary owner; previews first, and returns an undo token |
| `outlit_set_customer_access` | Set a member's access to a customer to viewer, editor, or none; returns an undo token |

### Activity and analysis

| Tool | What it does |
|---|---|
| `outlit_get_timeline` | Get the activity timeline for a customer, with `filters` for channel, event type and a time window (`within`, or `after` and `before`) |
| `outlit_list_facts` | Retrieve structured customer facts with `filters` for status, source type, public fact type and category and occurrence time, `page` pagination, and the `source` each fact came from (`type`, `id`, `occurredAt`, `quote`, and `permalink`) |
| `outlit_get_fact` | Retrieve one exact fact by ID as `{ customer, fact }`; `include: ["evidence"]` adds its first three cited excerpts, and `part` reads the rest |
| `outlit_get_source` | Retrieve one exact source record by the `source` (`type` and `id`) another tool returned |
| `outlit_list_sources` | List concrete source records such as calls, emails, calendar events, support tickets, Slack conversations, or opportunities |
| `outlit_search_customer_context` | Search across customer facts, emails, calls, calendar events, support tickets, Slack conversations, and CRM opportunities using natural language. Returns grouped artifact-level matches for `source` and `fact` results, with `filters` for source types and a time range, and `coverage` when nothing matches |
| `outlit_query` | Run read-only SQL queries against your customer data |
| `outlit_get_schema` | Get the analytics views with column units and currencies, view rules, event types and worked queries |

### Features

| Tool | What it does |
|---|---|
| `outlit_list_features` | Read configured Features and their sources; usage and event candidates on request, each with its own coverage |
| `outlit_create_feature` | Create one Feature from an exact product-event rule |
| `outlit_archive_feature` | Preview, then archive a non-final Feature using its current opaque revision |

### Feedback

| Tool | What it does |
|---|---|
| `outlit_submit_feedback` | Submit product feedback — bugs, ideas, or agent friction — to the Outlit team |

`outlit_submit_feedback` takes `body` (required, at most 20,000 characters), optional `area`
(at most 100 characters), and optional `context` (a JSON object of at most 16 KiB for
diagnostics — never secrets or unnecessary customer data). It returns `{ id, createdAt }`.
Submissions are authenticated and rate limited under a dedicated quota that does not consume
paid plan API-call quota. Feedback is product intake, not a support ticket, and does not
guarantee a reply.

MCP registers the entire public catalog, including customer ownership/access, Features, and the safe destination, integration (`outlit_list_integrations`, `outlit_setup_integration`, `outlit_get_setup_session`), settings (`outlit_get_settings`, `outlit_update_settings`) and activation preview capabilities described in [Workspace configuration](/ai-integrations/platform-actions). Archives and owner changes preview before they apply, and owner and access changes return an undo token. Feature creation and archive still require the underlying workspace permission and feature availability. See [Agents and AI overview](/ai-integrations/overview#read-vs-write-controls) for the public tool boundaries.
