"@outlit/cli": minor
---

Fail on input the CLI does not understand instead of ignoring it. An unknown flag, an extra or misplaced positional argument, a flag without its value, or an unknown subcommand now exits 1 before any request, naming the bad input, suggesting the closest valid flag, and listing the valid flags (as JSON on stderr when piped or with `--json`). For example, `outlit sources list acme.com --source-types call` used to return the whole workspace's newest sources; it now fails and suggests `--source-type` and `--customer acme.com`. Scripts that passed such input and relied on it being ignored now fail; fix the flag the error names. Input that worked before keeps working: the renamed spellings (`users list`, `--customer-id`, `--top-k`, `--mrr-above`, and the others) still run, camelCase spellings such as `--apiKey` or `--orderBy` are still accepted (and now keep their value, which was dropped when the flag had a default), and a flag typed before the subcommand, as in `outlit --json customers list`, is passed to the subcommand. A value that starts with `-` must now be attached (`--search=-draft`). Values that look like credentials are never echoed in these errors.

Every command that takes one customer accepts `--customer <domain|name|id>`, next to the existing `<customer>` positional where there is one: `customers get`, `customers set-owner`, `customers set-access`, `timeline get`, `identity get` and `facts list` gain it. Giving the positional and `--customer` with different customers fails, and a blank customer fails with `invalid_input` instead of meaning every customer (`people list --customer ""` used to list everyone). Shell completions now list exactly the flags each command takes, adding `--customer`, `--verbose`, `auth login --browser`, `feedback submit --idempotency-key`, `destinations update --type` and `upgrade --json`.
